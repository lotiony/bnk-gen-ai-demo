# BNK 데모 빌드 가이드 — Claude Code + KB GenAI React 코드 재사용

**목적**: 기존 KB GenAI 포털 React 코드를 출발점으로, `2026-08-25-handoff-bnk-genai-platform-demo.md`의 스펙대로 BNK 제안설명회(2026-09-09) 시연 데모를 Claude Code로 빌드한다.
**이 파일의 위치**: KB 코드를 복사한 작업 리포지토리의 `docs/` 폴더에 핸드오프 파일과 함께 둔다.

---

## 0. 구현 형태 변경 안내 (핸드오프 문서 대비)

핸드오프 문서는 "단일 HTML 프로토타입(처음부터 작성)"으로 확정했으나, **KB GenAI React 코드 재사용으로 구현 경로를 변경한다.** 요구의 본질은 "단일 HTML"이 아니라 **"발표장에서 네트워크 없이 더블클릭으로 열리는 데모"**이므로, React로 개발하되 **빌드 산출물을 오프라인 자립형으로 만들면 동일하게 충족**된다.

- Vite 기반이면: `vite-plugin-singlefile`로 **단일 index.html 출력** (권장)
- 단일 파일이 불가한 스택이면: 정적 빌드(`dist/`) 전체를 USB로 이동, 로컬 정적 서버 또는 `file://`로 구동. 외부 CDN·폰트·이미지 참조가 0건이면 요건 충족
- 나머지 제약(1280×720 판독성, Chrome/Edge, localStorage 금지, mock 데이터 중앙화, 실데이터 금지)은 핸드오프 문서 §3 그대로 유효

## 1. 시작 절차 (사람이 하는 일)

### 1-1. 작업 리포 준비 — KB 원본을 직접 건드리지 않는다

```bash

cd ~/work/bnk-genai-demo

# 2) 새 git 이력으로 시작 (KB 이력·리모트 분리)
rm -rf .git
git init && git add -A && git commit -m "seed: KB GenAI portal mockup 복사본"

# 3) 컨텍스트 문서 배치
mkdir -p docs
# 여기에 두 파일을 넣는다:
#   docs/2026-08-25-handoff-bnk-genai-platform-demo.md  (핸드오프)
#   docs/BNK_DEMO_CLAUDE_CODE_GUIDE.md                  (이 파일)
```

> KB 리포에 리모트가 연결된 채 작업하면 BNK 커밋이 KB 쪽으로 흘러갈 수 있다. `.git` 제거 후 재초기화가 가장 안전하다.

### 1-2. Claude Code 실행 및 초기화

```bash
cd ~/work/bnk-genai-demo

### 1-3. 킥오프 프롬프트 (복사해서 사용)

```

## 2. CLAUDE.md에 넣을 내용 (리포 루트)

`/init`이 만든 초안에 아래 블록을 병합한다. 이 내용이 모든 세션의 기본 규칙이 된다.

```markdown
# BNK GenAI Platform 시연 데모

KB GenAI 포털 mockup을 개조해 만드는 BNK금융지주 제안설명회(2026-09-09) 시연 데모.
스펙의 원천은 docs/2026-08-25-handoff-bnk-genai-platform-demo.md — 화면 구성이나
요건이 궁금하면 항상 이 파일을 먼저 확인할 것.

## 절대 규칙
- 오프라인 자립형: 외부 CDN·웹폰트·원격 이미지·외부 API 호출 금지.
  새 의존성을 추가할 때도 번들에 포함되는 것만.
- localStorage/sessionStorage/IndexedDB 사용 금지. 상태는 메모리(스토어)만.
- KB 브랜드 요소(로고·컬러·문자열·계열사명) 절대 잔존 금지. 발견 즉시 제거.
- 실제 금융사 데이터·실제 내규 문서 사용 금지. mock은 전부 가상 창작물.
- BNK 로고 이미지를 만들거나 삽입하지 않는다. 텍스트 워드마크로만 표기.
- 데모에 넣는 기능 = 제안 확약이다(RFP: 제안서는 계약서와 동일 효력).
  핸드오프 §2의 14화면 범위를 벗어나는 기능을 임의로 추가하지 않는다.

## Mock 데이터
- 모든 mock은 src/mock/ 아래 모듈로 중앙화. 컴포넌트에 하드코딩 금지.
  (시연 직전 문구 수정이 잦다 — 한 곳만 고치면 되게 유지)
- 테넌트 구조: 계열사 10개(가상 표기: 부산은행·경남은행 + 8개 계열사) + 그룹 공통,
  합계 11개 Namespace 구조가 화면에 드러나야 한다.

## 화면 ↔ 요건 추적
- 각 데모 화면 컴포넌트 상단에 대응 RFP 요건 ID를 주석으로 명시
  (예: // RFP: RAG-007, AGB-006① — Graph RAG 근거 그래프)
- 이유: 제안서 조견표와 상호 참조 검증에 사용

## 검증
- 완료 판정 전 반드시: ① `npm run build` 성공 ② dist를 네트워크 차단 상태로
  열어 전 화면 동작 ③ 1280×720 뷰포트에서 텍스트 판독 가능
- 개발 서버 확인만으로 "완료"라고 보고하지 말 것
```

## 3. 작업 순서 (Claude Code에 지시할 마일스톤)

핸드오프 §2의 우선순위(P0 → P1 → P2)를 따르되, React 재사용 특성상 리브랜딩을 먼저 끝낸다.

### M0. 인벤토리 (§1-3 킥오프 프롬프트) — 0.5일
산출: `docs/INVENTORY.md`. 이후 모든 판단의 기준.

### M1. 디브랜딩 + 리테마 — 0.5일
```
INVENTORY.md의 KB 흔적 목록을 전부 제거하고 BNK 데모용 중립 테마로 교체해라.
- 브랜드명: "BNK금융그룹 공동 생성형 AI 플랫폼" (텍스트 워드마크)
- 테넌트: 부산은행, 경남은행, BNK캐피탈 등 10개 계열사 + 그룹 공통 셀렉터
- KB 잔존 문자열 0건을 grep으로 증명해라 (kb, KB, 국민, kookmin 등)
```

### M2. P0 화면 3종 — 3~4일 (데모의 승부처)

**M2-1. Graph RAG 근거 그래프 (화면 3·4)** — 가장 먼저, 가장 공들여서.
```
규정/책무 어시스턴트 질의 화면을 만들어라.
- mock 규정 데이터셋: 가상 규정 12건, 규정 간 참조/개정 전후/전결권 관계를
  노드-엣지 그래프 구조로 src/mock/regulations.ts 에 설계
- 질의 입력 → 답변 스트리밍 연출 → 근거 그래프 패널이 열리며 관련 노드·엣지
  하이라이트 → 노드 클릭 시 규정 원문 발췌 표시
- 그래프는 인라인 SVG 또는 번들 포함 가능한 경량 라이브러리로. 외부 CDN 금지
- 핵심 메시지: "확률적 추측이 아니라 규칙과 계산으로 확정" — 답변의 모든
  문장에 근거 노드가 연결되어 있음을 시각적으로 보여줄 것
```

**M2-2. 승인 기반 DB 동적 라우팅 (화면 9)**
```
에이전트 상세 화면에 Draft/Approved 상태 토글을 만들어라.
- Draft: 접근 데이터가 100% 익명화된 개발 DB (마스킹된 값 표시)
- Approved + 동의 권원 확인: 운영 DB 복호화 데이터 (원본 값 표시)
- 좌우 대비 레이아웃으로 같은 쿼리의 결과가 상태에 따라 달라지는 것을 한 화면에
- 2중 승인(승인권자 결재 + 권원 확인) 플로우를 상단 스텝퍼로 표현
```

**M2-3. AI 거버넌스 포탈 (화면 14)**
```
AI기본법 대응 거버넌스 포탈 화면을 만들어라.
- Flow Diagram: 기획→개발→평가검증→운영→종료 단계, 각 단계 클릭 시 설명·결재선
- 대시보드: 전체 AI서비스 수, 고위험/고영향 AI 수, 위험등급별(고/중/저),
  연 1회 모니터링 기일 도래 관리
```

## 4. Claude Code 운영 팁 (이 프로젝트 기준)

- **화면 단위로 세션을 짧게.** 한 세션에 여러 화면을 섞으면 컨텍스트가 흐려진다. 화면 하나 끝나면 커밋하고, 필요하면 `/clear` 후 다음 화면. CLAUDE.md가 맥락을 유지해준다.
- **복잡한 화면은 Plan Mode 먼저.** M2-1(Graph RAG) 같은 건 바로 코드를 시키지 말고 plan mode로 설계안(데이터 구조·컴포넌트 분해·연출 순서)을 받고 승인 후 구현시킨다.
- **스크린샷 피드백 루프.** 화면이 나오면 브라우저 스크린샷을 찍어 Claude Code에 붙여넣고 "이 부분을 이렇게 고쳐라"로 지시하는 것이 텍스트 설명보다 빠르다.
- **mock 문구는 직접 고쳐도 된다.** src/mock/에 중앙화되어 있으므로 시연 전날 문구 손질은 에디터에서 직접 하는 게 빠르다.
- **커밋 규율.** 마일스톤 단위 커밋 + 리허설 통과 시점에 태그(`demo-v1`). 시연 직전 수정이 망가지면 태그로 롤백한다.
- (선택) AxDD Harness의 Claude Code 어댑터·Role Pack을 쓰는 조직 표준이 있다면 M0 시점에 함께 로드해도 된다. 단 이 데모는 mockup이므로 L1~L3 검증 게이트 전체를 태울 필요는 없다.
