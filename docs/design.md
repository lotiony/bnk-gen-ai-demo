# 디자인 시스템 — BNK 부산은행 웹 톤

레퍼런스 스크린샷에서 **픽셀 히스토그램으로 실측 추출**했다(추정값 아님). 데모 전 화면이 이 토큰만 쓰도록 하고, 값 조정은 `tailwind.config.js` 한 곳에서 한다.

> **로고 취급**: 색·레이아웃 언어는 차용하되 **BNK 로고 아트워크(스타일라이즈된 K)는 재현하지 않는다.** 워드마크는 텍스트로만 표기한다 — 핸드오프 §5 및 CLAUDE.md 규칙 유지.

---

## 1. 실측 결과

레퍼런스 이미지(2362×1512) 전 픽셀을 2px 간격 샘플링한 빈도다.

| 색 | 출현 | 역할 |
|---|---|---|
| `#FFFFFF` | 728,183 | 기본 배경 |

| `#F6F6F6` | 28,986 | 라이트 서피스 |
| **`#CB2C10`** | **12,295** | **주색(BNK 레드)** — 솔리드 채움·활성 상태·구분 룰 |
| `#000000` | 8,497 | 강한 구분선(사이드바 상단 룰) |
| `#FBF9FA` | 6,201 | 니어 화이트 |
| `#212121` | 3,226 | 제목 텍스트 |

## 2. 토큰

### 2.1 브랜드(레드)

| 토큰 | 값 | 출처 | 용도 · 텍스트 색 |
|---|---|---|---|
| `brand` | `#CB2C10` | 실측 | 솔리드 채움, 활성 탭, 주 CTA → **`text-white`** |
| `brand-dark` | `#A82410` | 파생(hover/press) | hover·press, 보더, 강한 룰 → **`text-white`** |
| `brand-strong` | `#FF3312` | 실측 | 워드마크 등 최상위 강조(희소 사용) |
| `brand-tint` | `#FBE9E6` | 파생 | 연한 레드 배경 → `text-ink` |
| `brand-bg` | `#FDF6F4` | 파생 | 니어화이트 레드 틴트 → `text-ink` |

> ⚠️ **`brand`·`brand-dark` 위에는 반드시 흰 텍스트.** 원본(KB 옐로우)은 밝은 배경 + 어두운 텍스트 구조라 `bg-brand … text-ink` 조합이 180여 곳 있었다. 레드로 바꾸며 해당 문자열의 텍스트를 전부 `text-white` 로 뒤집었다. 새 코드에서도 이 규칙을 지킬 것.

### 2.2 중립

| 토큰 | 값 | 용도 |
|---|---|---|
| `ink` | `#212121` | 제목 |
| `ink-dark` | `#333333` | 본문 |
| `ink-mid` | `#666666` | 보조·캡션 |
| `ink-light` | `#999999` | 비활성·플레이스홀더 |
| `line` | `#E0E0E1` | 기본 보더 |
| `line-soft` | `#EFEFEF` | 약한 구분선 |
| `line-warm` | `#D3D3D0` | 웜 블록 내부 보더 |
| `line-strong` | `#212121` | 사이드바 상단 등 강한 룰 |
| `surface` | `#F6F6F6` | 페이지 배경 |
| `surface-soft` | `#FBF9FA` | 카드 내부 옅은 영역 |
| `warm` | `#EFEEEB` | 배너·강조 블록 |

### 2.3 상태색 (기존 유지 — 레퍼런스에 대응색이 없음)

`ok #1B8A4D` / `warn #C9760F` / `bad #D8313D` / `info #1F5BB8`

> `bad`(#D8313D)와 `brand`(#CB2C10)가 가깝다. **오류/위험 표시에는 `bad`, 브랜드 강조에는 `brand`** 로 역할을 분리하고, 한 화면에서 두 색이 인접하지 않게 한다. 특히 가드레일 차단 이력(화면 13)·PII 차단(화면 5)에서 주의.

### 2.4 정보 스트립

레퍼런스의 안내 문구 띠: 배경 `#CBDDF7` 계열, 텍스트 `info`. 기존 `info-bg`(#E8F0FF)를 `#E8F0FB` 로 살짝 맞췄다.

## 3. 형태 — 각진 마감

레퍼런스는 **모서리를 거의 굴리지 않는다.** 버튼·탭·카드가 사각이고, 둥근 것은 아바타·챗봇 버블뿐이다. 원본 mockup은 `rounded-md`(6px)를 광범위하게 써서 인상이 물렀다.

Tailwind `borderRadius` 스케일을 재정의해 **클래스를 한 줄도 안 고치고 전 화면 마감을 바꿨다**:

| 클래스 | 기존 | 변경 |
|---|---|---|
| `rounded-sm` | 2px | **1px** |
| `rounded` | 4px | **2px** |
| `rounded-md` | 6px | **2px** |
| `rounded-lg` | 8px | **3px** |
| `rounded-xl` | 12px | **4px** |
| `rounded-full` | 9999px | **유지** (아바타·카운트 배지) |

## 4. 컴포넌트 패턴 (레퍼런스에서 도출)

| 패턴 | 규칙 |
|---|---|
| **주 CTA** | `bg-brand text-white`, 사각, 보더 없음. hover `bg-brand-dark` |
| **보조 버튼** | `bg-white text-ink-dark border border-line`, 사각 |
| **활성 탭** | `bg-brand text-white` 솔리드 채움 / 비활성 `bg-white text-ink-mid border-line` |
| **GNB 활성** | 레드 텍스트 + 하단 레드 보더. GNB 블록 전체 아래에 **2px 레드 룰** |
| **사이드바** | 상단에 **2px 짙은 룰**(`line-strong`), 항목 간 얇은 구분선, 활성 항목만 레드 텍스트 |
| **브레드크럼** | 마지막(현재 위치) 항목만 레드 |
| **섹션 구분** | 목록 상단에 얇은 레드 룰 |
| **안내 스트립** | 라이트 블루 배경 + `info` 텍스트, 사각 |
| **강조 블록** | `warm`(#EFEEEB) 배경 |

## 5. 타이포그래피

- **Pretendard Variable** 번들 인라인 (환경 무관 동일 렌더 — INVENTORY §5-3)
- 레퍼런스는 굵기 대비가 강하다: 제목 800~900, 라벨 700, 본문 400~500
- 기존 본문 13px / `xxs` 10px / `2xs` 10.5px 스케일 유지

## 5-1. 대응 해상도 — 1920×1080

2026-08-25 에 1280×720 → **1920×1080** 으로 상향했다. 페이지 컨테이너 `max-w` 를 1440 → **1760px** 으로 넓히고(1280→1600, 1120→1400), 온톨로지 그래프 패널 높이를 430→560 / 440→600px 로 키웠다. 폰트 스케일은 그대로 두었다 — Pretendard 를 번들에 인라인해 두어(§5) 해상도가 바뀌어도 자간·줄바꿈이 일정하다.

## 6. 적용 범위와 한계

**적용 완료**: 컬러 토큰 전량, `bg-brand` 계열 텍스트 대비 반전, borderRadius 스케일, 하드코딩 차트 색.

**미적용(의도적)**:
- 레퍼런스의 사이드바 상단 검정 룰·브레드크럼 레드 처리 등 **개별 컴포넌트 디테일**은 해당 화면을 제작·개조할 때(M2~M4) 함께 반영한다. 지금 전 화면에 일괄 적용하면 아직 만들지 않은 화면과 어긋난다.
- 레퍼런스는 공개 웹(B2C)이고 데모는 사내 운영 콘솔(B2B)이다. 정보 밀도가 달라 **여백·폰트 크기를 그대로 옮기지 않았다.**
